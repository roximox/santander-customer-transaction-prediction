## Discussion
 
We discussed the two available options, Kaggle Porto Seguro and Kaggle Santander, and agreed to work together on the Santander project. From there, we split the work into complementary scientific areas so that every member would have an identifiable contribution and an ML task of their own.
 
We planned the work packages to support parallel progress, with common evaluation and documentation conventions to be refined later. Since this was the initial planning meeting, no technical implementation or model evaluation had happened yet.
 
## Decisions
 
Santander was selected as the common project for all four members. We split responsibilities across four areas, each including an ML contribution:
 
- **Member 01** — project setup, data engineering, and reproducibility, with Logistic Regression.
- **Member 02** — exploratory data analysis, with Random Forest and Extra Trees.
- **Member 03** — feature engineering and dimensionality reduction, with PCA, feature selection, and Logistic Regression.
- **Member 04** — model optimization and evaluation, with Gradient Boosting / HistGradientBoosting.
We agreed to maintain a common methodology and reproducibility standard across the team. Major scientific results and the final model selection will be discussed jointly at a later stage; the detailed implementation follows from this initial planning.
 
## Task Assignment
 
- **Member 01** will plan the common technical foundation, including reproducible dataset access and data handling, the validation strategy, initial ML baselines, and Logistic Regression.
- **Member 02** will plan the exploratory data analysis: descriptive statistics, visualization and data understanding, correlation and variable analysis, and tree-based models.
- **Member 03** will plan feature engineering, PCA, feature selection, reduced-feature modeling, and the later comparison of reduced versus original feature representations.
- **Member 04** will focus on Gradient Boosting / HistGradientBoosting, and later on model optimization, diagnostic evaluation, and model comparison.
All members will take part in team meetings, code review, personal logbook documentation, scientific discussion and interpretation, portfolio preparation, and final-presentation preparation.
 
## Risks and Blockers
 
The main early risks are dependence on shared data and validation conventions, inconsistent evaluation between members, and coordinating shared modules and interfaces. The team needs to avoid data leakage and premature use of test data during model development.
 
No concrete technical blocker has come up yet, since development has not started.
